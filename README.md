# 3秒ダイアリー（仮）

日常の動画を何本か選ぶと、それぞれ好きな3秒ずつ切り出して1本の動画につなげるアプリ。
参考: iPhoneアプリ「Film Log」。

## いまの段階（試作 v0.3）

ブラウザだけで動く Web アプリ（PWA）。Android の Chrome（メイン端末: Galaxy S24 Ultra）、iPhone の Safari、PC の Chrome で動く。
動画はサーバーに送らず、すべて端末の中で処理する。

できること
- 動画を複数まとめて選ぶ、≡ をつかんでドラッグで並べ替え、日付順に並べる
- 「つくる動画の形」が縦なら横向きの動画を、横なら縦向きの動画を自動で外す（「これも使う」で戻せる。正方形はどちらも使う）
- 1本ずつ編集する画面（タブ切り替え）
  - 範囲: フィルムストリップ上のオレンジ枠をドラッグ、0.1秒/0.5秒の微調整、日付の修正
  - 色味: 8種（なし/フィルム/夕暮れ/ふんわり/あざやか/クール/モノクロ/セピア）、フィルムの粒子、ふちを暗く、日付スタンプ（全クリップ共通）
  - 細かく調整: 明るさ・コントラスト・彩度・色温度・色あせのスライダー（選んだ色味に重ねてかかる。全クリップ共通）
  - 文字: 18書体（Google Fonts）、8色、大きさ、そのまま/影/ふち/帯、画面上でドラッグして位置を決める、「この書式を全部に」
  - プレビューは書き出しと同じ見た目
- オープニング（予告編のような導入部）: 選んだ動画から 4/6/8 カットを 0.3/0.5/0.8 秒ずつ自動で並べ、タイトルと日付の範囲（あり/なし）をのせる。最後は黒へフェード。オープニングの間は動画の音を消してBGMだけ
  - カットは各動画の「使う部分」の真ん中あたりから取る。動画がカット数より少ないときは同じ動画の別の場面を使う
- 仕上がり: 1本の長さ 1/2/3/5秒、縦・横・正方形、いっぱいに/全体を入れる、切り替え（パッと/ふわっと/ピカッと）、画質 720p/1080p
- 音: 動画の音量（0〜100）。BGM はスマホの中の音楽ファイルを選び、流し始めの位置・音量・フェード（始まり1秒／終わり2秒）を設定、試聴できる。曲が短いときはくり返す
  - BGM は録画している区間だけ流し、曲の位置を「録画した長さ」でつなぐので、動画とずれない
- 「書き出す前にプレビュー」：録画せずに、つないだ映像と音を再生して確認できる
- 設定・文字の書式は端末に保存される
- 選んだ動画と編集内容（範囲・日付・文字・並び順など）を IndexedDB に自動保存し、ページが閉じられても次に開いたとき元に戻す
  - 動画を保存できなかったものは名前を表示し、同じ動画（名前と大きさで判定）を選び直すと編集内容ごと戻る
  - 「最初から」で保存した内容をすべて消す
- mp4 で書き出し → 保存・共有（https のときのみ。Android Chrome の共有は50MBまでなので、超えるときはダウンロードを案内）/ダウンロード（完了のお知らせを表示）
- ホーム画面に追加できる（manifest + Service Worker。https で公開したときに有効）

- `index.html` … アプリ本体（HTML/CSS/JS 1ファイル）

- `manifest.webmanifest`, `sw.js`, `icon-192.png`, `icon-512.png` … ホーム画面に追加・オフライン用
  - アプリを更新したら `sw.js` の `VERSION` を上げる

## 動かし方（PC で確認するとき）

```bash
python -m http.server 8000
```

- PC: http://localhost:8000
- スマホ（同じ Wi-Fi）: http://<PCのIPアドレス>:8000

## 仕組みと既知の制約

- 書き出しは2つの方法がある。
  1. **速い書き出し（`buildFast`、ふだんはこちら）**：WebCodecs を使う。mp4box.js で動画の目次だけを読み、必要な区間のコマだけをファイルから取り出して
     VideoDecoder → canvas で色味・文字をのせる → VideoEncoder（H.264）→ mp4-muxer。音は AudioDecoder で取り出し、OfflineAudioContext で BGM と混ぜて AudioEncoder（AAC、なければ Opus）。
     再生を待たないので、完成動画の長さより短い時間で書き出せる。スマホの回転情報（tkhd の matrix）も反映する。30コマ/秒にそろえる。
  2. **いつもの書き出し（`build`）**：`<canvas>` に描きながら `MediaRecorder` で録画する。完成動画の長さと同じだけ時間がかかる（＋各クリップの助走0.5秒）。
     速い書き出しが使えない・失敗したときに自動でこちらに切り替える。プレビューもこの方法。
  どちらも、書き出し中に画面を閉じると失敗する。
- 各クリップは開始位置の0.5秒手前から再生し、映像が流れ出してから録画を再開する（冒頭のカクつき対策）。
  開始位置が0秒のクリップは、最初の約0.1秒が使われない。
- 描画は最大30コマ/秒。文字と日付は1枚の画像にまとめておき、毎コマ重ねるだけにしている（軽量化）。
- Chrome の MediaRecorder が作る MP4 は細切れ形式（fragmented MP4）で、全体の長さが 0 になっている。
  そのままだとギャラリーで「0:03」などと表示されるので、書き出し後に mp4box.js で中身を取り出し、mp4-muxer で普通の MP4 に組み直している（`fixMp4`）。
- 撮影日の決め方：①ファイル名の日付（Galaxy: 20261013_153012.mp4）→ ②動画の中の撮影日時（moov/mvhd の作成日時）→ ③ファイルの更新日時。
  ギャラリーから選ぶと更新日時が「選んだ日」になることがあるので②を使う。手で直した日付（dateEdited）は自動で書き換えない。

## 配布の方針（2026-10-14 時点）

- 第一目標: Google Play。できれば App Store にも出す。
- 想定: この Web アプリを Capacitor でアプリ化（Android は Windows だけでビルド可能）。
  iOS のビルドには Mac かクラウドの Mac ビルドサービスが必要。Apple Developer Program は年 $99。
- それまでは https で公開して、スマホだけで使えるようにする。
